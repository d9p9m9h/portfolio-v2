## Quality မကျအောင် ထိန်းရမည့် စည်းမျဉ်းများ

### မလုပ်ရ

- တစ်ခါတည်းမှာ တစ်ခုလုံးကို ပြီးအောင် မလုပ်ပါနဲ့
- chat memory ကို အဓိက မမှီခိုပါနဲ့
- session state မတင်ဘဲ အလုပ်ဆက်မလုပ်ပါနဲ့
- Bootstrap/styled-components ကို ပြန်မထည့်ပါနဲ့
- ဆုံးဖြတ်ချက်တွေကို ဖိုင်ထဲ မမှတ်ဘဲ မထားပါနဲ့

### လုပ်ရ

- တစ်ခါတည်းမှာ task တစ်ခုပဲ လုပ်ပါ
- ပြီးတိုင်း `SESSION_STATE.md` ကို update လုပ်ပါ
- ဆုံးဖြတ်ချက်အသစ်ရှိရင် `DECISIONS.md` ထဲ ထည့်ပါ
- design/requirement အသစ်ရှိရင် `PROJECT_CONTEXT.md` ထဲ ထည့်ပါ
- လုပ်ရမည့်အဆင့်သစ်ရှိရင် `IMPLEMENTATION_PLAN.md` ထဲ task ID နဲ့ ထည့်ပါ

## အကျဉ်းချုပ်

အခုလိုလုပ်ထားရင် —

Chat အသစ်ဖွင့်လည်း

- ဘာလုပ်နေတယ်

- ဘယ်နေရာရောက်နေတယ်

- နောက်တစ်ဆင့်ဘာလဲ

- ဘာစည်းမျဉ်းတွေရှိတယ်

- ဘာတွေပြီးပြီ

- ဘာတွေမလုပ်ရသေးဘူး

ဆိုတာ အားလုံး **project ရဲ့ ဖိုင်တွေထဲမှာ** ကျန်နေမယ်။

ဒါကြောင့် **context window limitation** ကြောင့် အရည်အသွေးကျနိုင်တဲ့ ပြဿနာကို အများကြီး လျှော့ချနိုင်ပါတယ်။
